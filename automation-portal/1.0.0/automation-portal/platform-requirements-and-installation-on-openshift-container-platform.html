Platform Requirements and Installation on OpenShift Container Platform

The Automation Portal for Ansible Automation Platform (AAP) 2.7 provides a centralized interface for managing automation workflows, visual environment building, and content discovery. When deploying on OpenShift Container Platform (OCP), the Automation Portal leverages the Kubernetes-native architecture to ensure scalability, high availability, and seamless integration with existing AAP controller components.

Prerequisites and Requirements

Before initiating the deployment, ensure your environment meets the following technical requirements:

  • Platform Subscription: Valid Red Hat Ansible Automation Platform subscription.

  • Existing AAP Infrastructure: An active instance of AAP 2.6+ to facilitate authentication and integration.

  • OpenShift Environment: Access to an OpenShift Container Platform cluster (version 4.12–4.17+).

  • Permissions: Cluster-level permissions to create OAuth applications within the target project.

  • CLI Tools:

  • oc CLI tool for OpenShift management.

  • helm (version 3.10 or newer) for package deployment.

Installation Overview

The official deployment method uses Helm charts on OpenShift Container Platform. The Helm chart automates the deployment of the Automation Portal, handling networking, storage, and integration with your AAP instance.

Two-Phase Installation Process:

  1. Phase 1 - Prerequisites: Complete Hands-on Setup: Deploying Automation Portal - Prerequisites and Configuration to set up OAuth, API tokens, and OpenShift secrets.

  2. Phase 2 - Deployment: Deploy the Helm chart using Hands-on Lab: Installing and Verifying the Automation Portal on OCP.

Both phases are required for a successful installation.

Next Steps: Deployment and Configuration

Once you’ve completed the prerequisites, proceed with the actual deployment:

Step 1: Deploy via Helm Chart

Follow the detailed step-by-step guide in Hands-on Lab: Installing and Verifying the Automation Portal on OCP, which covers:

  1. Verifying your environment and secrets (Task 1)

  2. Deploying the Helm chart from the OpenShift repository (Task 2)

  3. Monitoring the deployment (Task 2, Step 2.4)

  4. Verifying the deployment health (Task 3)

Step 2: Post-Installation Configuration

After the deployment is complete, complete the critical post-installation steps in Hands-on Lab: Installing and Verifying the Automation Portal on OCP:

  1. Update OAuth Redirect URI (Task 4) — This is essential for authentication to work

  2. Access the Web Interface (Task 5) — Verify you can log in successfully

  3. Configure RBAC (Task 6, optional) — Set up role-based access policies

Step 3: Configure Advanced Features (Optional)

After the basic deployment is working, you can:

  1. Configure EE Builder: See Configuring EE Builder via Helm charts

  2. Set up Navigation Menus: See Managing RBAC-based Navigation Menus for User Role Separation

  3. Implement UI Policies: See Reducing UI Complexity through Admin-Defined Access Policies

Troubleshooting Guidance

Secrets Not Found Error

Problem: Deployment fails with "secrets-rhaap-portal not found"

Solution: Go back and complete the Hands-on Setup: Deploying Automation Portal - Prerequisites and Configuration lab to create the required OpenShift secrets.

Connectivity Issues

Problem: Portal cannot communicate with your AAP instance.

Solution: 1. Verify the aap-host-url in the secrets-rhaap-portal secret is correct 2. Test connectivity from the OpenShift cluster to your AAP instance 3. Check that the AAP instance is reachable on the network

Pod CrashLoopBackOff

Problem: The portal pod keeps restarting.

Solution: 1. Check the init container logs: oc logs <pod-name> -c install-dynamic-plugins -n portal 2. Verify that all secrets were created correctly 3. Check that image pull secrets are configured if using a private registry

For more detailed troubleshooting, see hands-on-lab-on-installing-and-verifying-the-automation-portal-on-ocp.adoc#_troubleshooting_guide
