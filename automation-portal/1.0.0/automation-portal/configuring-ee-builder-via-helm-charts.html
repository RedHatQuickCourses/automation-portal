Configuring EE Builder via Helm charts

Configuring EE Builder via Helm Charts

The Execution Environment (EE) Builder is a core component of the Ansible Automation Platform 2.7 Automation Portal. It abstracts the complexities of ansible-builder by providing a GUI-driven workflow for container image creation. To enable this functionality within an OpenShift Container Platform (OCP) environment, administrators must configure the Automation Portal via its Helm chart (or the associated Operator Custom Resource).

Architectural Overview

The EE Builder relies on the integration between the Automation Portal and the underlying OpenShift container registry and build pipelines. By configuring the Helm chart, you define the infrastructure necessary to: * Provision the builder service. * Define the OCI (Open Container Initiative) delivery mode for image management. * Establish the trust and synchronization between the Portal and your automation content sources.

Configuration Prerequisites

Before modifying your Helm chart configuration, ensure the following: * OpenShift Cluster Access: Cluster-admin privileges to modify the Automation Platform Operator instance. * Helm Access: Access to the deployment manifest (or the AutomationPlatform Custom Resource YAML if utilizing the Operator). * Namespace/Project: Ensure you are working within the namespace where the Automation Portal is deployed.

Configuration Procedure

To enable the EE Builder, you must edit the AutomationPlatform custom resource. Follow these steps:

  1. Access the Portal Configuration Navigate to the OpenShift Web Console, select the project where AAP is installed, and edit the AutomationPlatform custom resource YAML.

  2. Define the EE Builder Block Locate the spec section. You must ensure the ee_builder block is defined. Replace any placeholder URLs (e.g., apps.example.com) with your actual ingress domain.

spec:
  ee_builder:
    enabled: true
    # Configure the delivery mode for OCI-compliant images
    pluginMode: "oci"
    imageTagInfo: "latest"
  # Set the AAP organization for content synchronization
  sync:
    organization: "Default"

  1. Configure Red Hat Developer Hub Integration (Optional) If you are utilizing the Visual Builder’s integration with Red Hat Developer Hub for templating, ensure the global configuration is set to OCI mode:

redhat-developer-hub:
  global:
    pluginMode: "oci"
    imageTagInfo: "1.2.0" # Use the appropriate plugin version

  1. Apply Changes Save the YAML. The Operator will reconcile the state, rollout the necessary pods for the EE Builder, and expose the "EE Definitions" menu in the Automation Portal navigation pane.

Verification

Once the operator has finished the rollout, verify the installation:

  • Navigation Check: Refresh your browser. The "EE Definitions" tab should now be visible in the left-hand navigation menu of the Automation Portal.

  • Pod Status: Execute oc get pods -n <your-namespace> and confirm that the builder-related pods are in the Running state.

  • Service Readiness: Open the Automation Portal and click on "EE Definitions." If the UI loads without errors, the Helm configuration is successfully applied.

Troubleshooting Tips

  • Helm Validation Failures: If the deployment fails, verify that all placeholder strings (such as apps.example.com) have been replaced. Helm charts often include regex validations that will reject default template strings.

  • Permission Denied: Ensure the ServiceAccount associated with the EE Builder has the necessary image-puller and image-pusher roles within the OpenShift namespace.

  • Sync Errors: If the "Content Discovery" catalog is empty, re-verify the sync.organization setting in your Helm chart to match the organization defined in your Automation Controller.
